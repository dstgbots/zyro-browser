# 17 — Top 20 Architectural, Technical & Security Risks

This document catalogs the **Top 20 Critical Risks** identified during the architectural audit of Titanium Browser, along with concrete mitigation strategies for the future True Links project.

---

| # | Risk Title | Severity | Impact Description | Concrete Mitigation Strategy |
| :---: | :--- | :---: | :--- | :--- |
| **1** | **Sed Script Silent Matching Failure** | **CRITICAL** | `patch.sh` uses `sed -i 's/.../.../'`. If upstream Chromium refactors even one whitespace character or variable name, `sed` silently fails to replace text without returning an error code. The build continues and produces an unpatched, broken binary. | Add a post-patch assertion script (`verify_patches.py`) in `build.sh` that greps target files to guarantee every patch was applied successfully before `gn gen` runs. |
| **2** | **Chromium Upstream Milestone Fragility** | **CRITICAL** | Upgrading Chromium versions (e.g. M153 -> M154) frequently changes internal class hierarchies, JNI signatures, and file paths. Vanadium patches and Titanium sed scripts will fail to apply. | Pin the Chromium tag explicitly in `args.gn` and update only during scheduled, dedicated milestone maintenance sprints. |
| **3** | **CI/CD Compute Exhaustion (OOM Killer)** | **HIGH** | Linking multi-gigabyte native binaries (`libchrome.so`) with ThinLTO requires 24–32 GB of active RAM. Standard GitHub-hosted `ubuntu-latest` runners (14 GB RAM) will crash with exit code 137 (OOM). | Maintain dedicated `self-hosted` CI runners with at least 32–64 GB RAM and 150 GB fast NVMe SSD storage. |
| **4** | **Desktop Android (`is_desktop_android`) Assumptions** | **HIGH** | Enabling `is_desktop_android = true` enables desktop features but also activates tablet desktop windowing assumptions in upstream code, leading to null view anchors on phones. | Confine all mobile extension layout adaptations strictly to phone form-factor checks (`ui::GetDeviceFormFactor() == ui::DEVICE_FORM_FACTOR_PHONE`). |
| **5** | **Manifest V2 Code Eviction in Upstream Chromium** | **HIGH** | Google is systematically removing legacy MV2 C++ code (`browser_action`, declarative webRequest) from Chromium. Future milestones will completely delete these source files. | Transition True Links companion extensions to Manifest V3; maintain MV2 only as long as underlying C++ handler code exists. |
| **6** | **Low Memory Killer (LMK) Extension Terminations** | **HIGH** | Android devices under memory pressure kill background extension processes, causing adblockers and content scripts to silently stop working. | Ensure `SetPrimaryPageImportance(IMPORTANT, NORMAL)` patch remains active; keep bundled extension memory footprints minimal. |
| **7** | **Incognito Profile Teardown Use-After-Free (UAF)** | **HIGH** | Closing Incognito tabs while background extension scripts or WebContents observers still reference the OTR profile causes native heap corruption (`SIGSEGV`). | Preserve Titanium's `HasLiveWebContentsForBrowserContext` guard in `profile_destroyer.cc` and `tabs_api.cc`. |
| **8** | **Intent Scheme Injection Vulnerability** | **HIGH** | Malicious third-party apps can send crafted `content://`, `file://`, or `javascript:` intents to extract local browser databases or execute XSS. | Never remove or relax the `URLUtil.isNetworkUrl` check in `LaunchIntentDispatcherHooks.java`. |
| **9** | **Gradle vs. GN Build System Cognitive Mismatch** | **MEDIUM** | Android engineers accustomed to Gradle attempting to add dependencies via `build.gradle` will find their changes ignored because Chromium compiles using GN and Ninja. | Perform all Java dependency declarations inside `third_party/android_deps/` or write self-contained Java classes using Android framework APIs. |
| **10** | **Play Store Keystore Invalidation** | **MEDIUM** | If the signing keystore (`test.jks`) or alias parameters in CI secrets change, Google Play Store will permanently reject updates due to signature mismatch. | Securely backup signing keystores in encrypted cold storage with strict access controls. |
| **11** | **Build-Time Filter List Network Outage** | **MEDIUM** | If `easylist.to` or `adblockplus.org` is offline during CI execution, `filter_list_download.py` will fail, aborting the entire build. | Add local cached fallback copies of `filter_lists_easylist.txt` in the repository if remote downloads fail. |
| **12** | **Missing Google Play Services Crashes** | **MEDIUM** | Enabling Google-dependent features (Voice Search, Google Auth, Chrome Sync) without proprietary Play Services keys will cause immediate runtime crashes. | Keep `google_api_key = "x"` and `use_login_database_as_backend = true` to preserve local offline functionality. |
| **13** | **Unresponsive Desktop WebUI on Mobile Screens** | **MEDIUM** | Desktop WebUI pages (`chrome://extensions`, `chrome://flags`) render tiny or unscrollable on mobile screens without viewport injection. | Maintain Titanium's responsive CSS and mobile viewport injection patches in `patch.sh:L63-68`. |
| **14** | **Scoped Storage (SAF) Incompatibilities across Android Versions** | **MEDIUM** | Android 13/14/15 storage permission shifts can break unpacked extension directory loading from external storage. | Continue using `VirtualDocumentPath.java` tree URI abstractions rather than direct POSIX filesystem paths. |
| **15** | **Predictive Back Gesture Conflicts** | **LOW** | Android 14+ predictive back gestures can trigger tab closure before web page history navigation occurs. | Titanium explicitly deletes Vanadium's predictive back patch (`build.sh:L25`) to avoid navigation race conditions. |
| **16** | **Subresource Filter Ruleset Memory Bloat** | **LOW** | Compiling excessively large or redundant blocklists into `filter_lists_easylist.txt` inflates memory consumption in the browser process. | Curate and deduplicate filter list URLs; avoid importing multi-megabyte hostlists. |
| **17** | **WebView Shared Library Target Conflicts** | **LOW** | Building combined Trichrome WebView targets increases build time by 2x and complicates APK signing. | Retain Titanium's decision to build monolithic `chrome_public_apk` rather than Trichrome bundles. |
| **18** | **Native Crash Debuggability in Official Builds** | **LOW** | Official builds compile with `symbol_level = 1` and stripped native libraries, making tombstone stack trace symbolication challenging. | Archive the `out/Default/lib.unstripped/libchrome.so` debug symbol files as CI build artifacts for crash analysis. |
| **19** | **In-Tree Clang Toolchain Dependency Drift** | **LOW** | Host C++ compilers (`g++`/`clang`) cannot be used to compile Chromium; only the Google-pinned in-tree Clang is supported. | Always let `gclient runhooks` manage the compiler toolchain; never override Clang paths manually. |
| **20** | **Remote Configuration Injection Hijacking** | **LOW** | A future True Links dynamic config endpoint could be spoofed via Man-In-The-Middle (MITM) if not properly authenticated. | Enforce HTTPS with TLS certificate pinning and sign config JSON payloads with an asymmetric private key verified on-device. |
